## Синхронизация профиля через VPS — отложено

С другого компьютера: добавить тот же VPS (хост, логин, пароль/ключ) и забрать уже готовые команды, группы и связки, которые лежат **на самом сервере**.

Файл-заготовка: `src/core/remote_profile.hpp`. Тесты: `tests/test_remote_profile.cpp`. В меню, справке и настройках этого пока нет.

### Зачем

Сейчас всё живёт в `%APPDATA%\FaTTY\config.json`. Пароли завязаны на DPAPI этой учётной записи Windows, поэтому просто скопировать конфиг на другой ПК бесполезно, а экспорт — отдельный файл, который надо таскать с собой.

Идея: VPS сам хранит «шпаргалку» FaTTY по этому серверу. Учётные данные по-прежнему вводятся на каждом устройстве; с сервера приезжает только набор действий.

### Что кладём на VPS

Один JSON на сервер, путь: `~/.fatty/profile.json` (домашний каталог того пользователя, под которым заходим по SSH).

В файле:

- метаданные сервера **без секретов**: имя, хост, порт, логин, `remote_shell`, `health_enabled`;
- группы (имя, рабочий каталог);
- команды (текст, комментарий, папка, таймаут, login-shell, предупреждение, `cd`, оболочка);
- связки (имя, пауза, шаги по имени команды + группы).

Не кладём никогда:

- пароль, `password_blob`, путь к ключу, содержимое ключа;
- список **других** VPS;
- локальные пути (PuTTY, WinSCP, доп. программы);
- геометрию окон, тему, журнал, `health.json`, known_hosts.

Приложение-настройки вроде темы и «подтверждать разовую команду» остаются локальными. Если когда-нибудь понадобится таскать и их — отдельный файл на одном выбранном «хабе», не смешивать с профилем команд сервера.

### Как доставлять

Отдельный демон на VPS не нужен. Уже есть SFTP (`SFTPSession`).

1. **Выгрузить:** подключиться к выбранному VPS → создать `~/.fatty/` при необходимости → записать `profile.json` (права `0600`).
2. **Забрать:** то же подключение → прочитать файл → влить в локальный конфиг **только** для этой карточки VPS.
3. Кнопка в карточке / меню VPS: «Сохранить на сервер» / «Загрузить с сервера». Автосинхронизации в первой версии нет: иначе легко затереть правки с другого ПК.
4. После загрузки спросить режим:
   - **заменить** — команды, группы и связки этой карточки берутся из файла (пароль и ключ карточки не трогать);
   - **добавить недостающее** — совпадения по `(группа, имя команды)` и по имени связки пропускать.

Яйцо и курица нормальные: чтобы скачать профиль, карточка VPS уже должна быть (хост + логин + пароль/ключ). С другого устройства сначала добавляешь сервер, потом жмёшь «Загрузить».

### Сопоставление

Локальный `server.id` на разных ПК разный. В файле идентичность — `host` + `username` + `port`. При загрузке всё равно применяем к **выбранной** карточке: пользователь сам указал, с какого VPS читаем. Если хост/логин в файле не совпали с карточкой — предупредить, не молча писать в другую машину.

Шаги связки в файле — имена, не UUID. Так профиль переживает пересоздание id при импорте.

### Конфликты

Первая версия — только ручные кнопки, last-write-wins, в файле поле `updated_at`. Не пытаться трёхсторонне мержить текст команд. Если позже понадобится автообмен — сравнивать `updated_at` и спрашивать.

Права на файл: домашний каталог пользователя SSH. Не писать в `/etc` и не делать world-readable: в командах могут быть токены, пути, внутренние имена.

### Этапы включения в рабочую версию

1. **Сейчас (заготовка):** формат JSON, сборка из `Config`, разбор, `replace` / `merge` без секретов. Готово, UI нет.
2. SFTP: mkdir `~/.fatty`, запись/чтение текста по абсолютному пути, `chmod 0600`.
3. Две кнопки у выбранного VPS + диалог режима загрузки. Не предлагать это при каждом старте.
4. По желанию: при первом успешном SSH, если локально команд нет, а файл на сервере есть — один раз спросить «загрузить набор?».

Пока этап 3 не сделан, в changelog и справку не писать: для пользователя функции ещё нет.
